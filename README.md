# ポケポケ ★2サポート X需給ランキング — 過去7日遡及版

公開Xポストに書かれた「求 / 希望」と「譲 / 出 / 提供」を集計し、★2サポートの需要数・供給数・需要供給比を **24時間 / 48時間 / 1週間** でランキング表示するサイトです。

## v2.1 のポイント

この版は、設置した時刻以降の投稿だけを貯める方式ではありません。**初回実行時に現在時刻から直近7日を遡って取得**します。その後は30分ごとに新着を取り込み、約24時間ごとに7日分を再走査して取りこぼしを補完します。さらに、本文だけでなく**GameWithなどのトレード画像メーカー画像を日本語OCRで解析**し、画像内の「欲しいカード / 求」と「出せるカード / 譲」も集計対象にします。

Yahoo!リアルタイム検索は過去1か月以内の日本語の公開Xポストを検索対象にしています。本プロジェクトは、その検索結果のページネーションを使い、ランキングに必要な直近7日を遡ります。

## 集計の考え方

- X APIは使用しません。
- 公開Xポストの発見・取得は Yahoo!リアルタイム検索を利用します。
- 本文に「求 / 希望」と「譲 / 出 / 提供」の両方が明示されている投稿を解析します。
- `求: モノマネむすめ×2` は需要2として数えます。
- 同じXステータスIDは重複排除します。
- 画像にしかカード名がない投稿も、トレード画像メーカー形式と判定できた場合はOCRで解析します。
- OCRはTesseract.js（日本語+英語）を利用し、同じ画像は `docs/data/ocr-cache.json` にキャッシュして再解析を減らします。
- OCRで見出しとカード名の両方を十分に判定できない画像は、誤集計防止のため数えません。
- Yahoo!側の検索対象外・削除済み・非公開などは取得できないため、表示値は「取得できた公開投稿内の総数」であり、X全体の完全総数ではありません。

## 過去7日の取得方法

通常の広い検索語に加え、82種すべての★2サポートについてカード名別の検索も実行します。検索結果は1ページだけではなく `oldestTweetId` を使って古い方向へページ送りし、次のどちらかになるまで進みます。

1. 7日前より古い投稿に到達する
2. Yahoo!側でそれ以上の結果が返らなくなる

検索結果が非常に多く安全上のページ上限に達した場合は、サイトの「過去データ遡及」が「一部上限」と表示されます。`config/history.json` の上限値を増やして `npm run backfill` を再実行できます。

## 最初にやること（GitHub + Netlify）

1. ZIPを展開し、中身をGitHubリポジトリへアップロード
2. Netlifyで **Add new project → Import an existing project → GitHub** からそのリポジトリを選択
3. NetlifyのPublish directoryは `docs`（`netlify.toml` に設定済み）
4. GitHubで **Actions → Collect X trade data → Run workflow** を1回実行
5. 初回は自動的に現在より前の7日も遡って収集
6. 以後は毎時17分・47分に自動収集。NetlifyはGitHubの更新を検知して再デプロイ

### 手動で7日分を取り直す

GitHub Actions の **Force 7-day historical backfill** を実行します。

ローカルなら:

```bash
npm test
npm run backfill
```

通常収集:

```bash
npm run collect
```

## NetlifyへZIPを直接ドラッグする場合

画面自体は公開できますが、NetlifyへのZIP手動アップロードだけではGitHub Actionsが動かないため、ランキングは自動更新されません。**過去7日取得 + 30分ごとの自動更新まで使う場合はGitHub連携が必要です。**

## 設定

- 対象カード: `config/cards.json`
- 通常検索語: `config/queries.json`
- 履歴取得設定: `config/history.json`
- 直近収集: `scripts/collect.mjs`
- 7日遡及: `scripts/backfill.mjs`
- Yahoo取得処理: `scripts/yahoo.mjs`
- 画像OCR: `scripts/image-ocr.mjs`
- 表示: `docs/`

`config/history.json` の主な項目:

- `rankingHorizonHours`: 168 = 1週間
- `storageHorizonHours`: 192 = 8日保存
- `autoBackfillEveryHours`: 24 = 1日ごとに7日を再走査
- `imageOcrEnabled`: 画像OCRのON/OFF
- `imageOcrMaxNewImagesPerRun`: 1回の実行で新規OCRする画像数の上限
- `recentPagesPerQuery`: 通常更新時のページ数
- `broadBackfillPagesPerQuery`: 広い検索語の履歴ページ上限
- `cardBackfillPagesPerQuery`: カード別検索の履歴ページ上限

## 需要供給比

`需要 ÷ 供給` を表示します。供給0かつ需要ありは `∞` と表示し、ランキングでは上位側に置きます。小標本を除きたい場合は画面の「合計2件以上 / 5件以上 / 10件以上」を使用できます。

## 注意

Yahoo!リアルタイム検索のページネーション用エンドポイントは公開サイト内部で使用されている認証不要の取得先を利用しています。Yahoo!側の仕様変更で動かなくなる可能性があるため、取得エラーは `docs/data/state.json` とサイト表示で確認できるようにしています。


## OCR強化版のポイント

- 画像全体OCRだけでなく、**拡大・グレースケール化・二値化・分割クロップ**を組み合わせてOCRします。
- ポケポケトレードメーカーのような**小さいカード画像が複数並ぶ画像**に対応するため、上半分/下半分/左右/四分割/中央帯も個別にOCRします。
- 同じカードを複数のOCRパスで読んだ場合は**最大件数採用**にして、重複カウントを抑えます。
- OCRキャッシュにバージョンを持たせ、アルゴリズム更新後は再解析されます。


## 品質維持・低頻度モード

- 約4時間ごとに自動更新します。
- 8つの検索条件と画像OCRを維持します。
- 各検索は最大10ページ、24時間のフォールバック範囲を確認します。
- 過去7日一括バックフィルとカード別大量検索は停止します。
- 403/429では再試行・回避せず、その実行の残りの取得を停止します。
- 公開サイトの `docs/` には集計済み `rankings.json` だけを残し、個別の運用データは `.collector-data/` に移します。
- OCR結果は需要/供給判定だけ保持し、OCR本文プレビューは保存しません。
